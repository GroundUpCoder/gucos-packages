# Migration queue

`queue.json` is the live implementation ledger; the adjacent historical inventory
is immutable research input. Historical success does not establish platform 1.0
compatibility. Each row retains evidence references, state, acceptance records and
concrete blockers. `source-prepared` means files exist, not that a build passed.
`core-owned-excluded` avoids counting bootstrap twice. Existing packages require
scope auditing, not duplicate publication. Additional workloads are counted
separately from the 110 canonical historical names. Bundles/data are not counted
as separately compiled applications.

Core owner confirmed the browser hold released in cc operation
`01a1250a-0f24-7937-a981-8b242f04d5bd`. Browser work uses sequential machine-job
reservations. Unaccepted candidate recipes remain outside catalog.json. Publication
requires immutable inputs, dependency/provider closure, independent review and
real guest source/build/install/run/relink/reload acceptance as applicable.
Baseline19 catalog/artifact bytes and their original provenance are preserved.

Live-accepted publications now include six initial foundations, five missing
X clients, six GLib foundations, six graphics foundations and four GIO/ATK/FriBidi
packages. These27 package entries are not27 canonical historical names: the X
clients complete components of a historical bundle and cJSON is an additional
noncatalog workload. Per-item state and scope live in queue.json and batch evidence.

The remaining queue is open. GTK, Python, games and host-prepared C++ closures
still require real acceptance. Never substitute guest C compilation for
historical host C++ preparation or treat source review as runtime acceptance.
